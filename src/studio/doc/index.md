# 量潮职位管理工作台

## 定位

按《职位》手册（`docs/tutorial/role/title.md`）实现的职位管理系统原型：
以「职位 — 任职 — 主要职位」三个概念为骨架，把手册的定义与工作习惯落成可操作的记录工具。

> 习惯先于工具：职位记录先在 Markdown 事实源中做实，工具是习惯的载体，不是替代品。

工作台本身不持有权威数据。本原型以内存事实源（`sample_data.dart`）替代 git 数据层，
用于验证记录口径与交互；正式形态下应由岗位档案（职位说明书）与职务单一事实源（任职事实）供数。

## 领域概念

| 概念 | 定义（手册口径） | 落点 |
|---|---|---|
| 职位 | 有名称、有归属、有职责边界的一段职责与权限；槽位而非人头 | `Position` |
| 机构 | 职位的归属单位（联盟、实训基地、公司） | `OrgUnit` |
| 任职 | 成员与职位的对应关系；一人可兼任多职 | `Appointment` |
| 主要职位 | 成员所任职位中唯一代表职位，决定首要称谓与优先次序 | `Appointment.primary` |
| 变更登记 | 新任、免任、主要职位变更一经发生即登记，注明生效日期与依据 | `ChangeRecord` |
| 汇报关系 | 兼任边界显式：汇报关系按职位分别登记 | `Appointment.reportsToId` |

## 工作习惯 → 功能映射

| 手册约定 | 系统行为 |
|---|---|
| 槽位先于人头 | 「新建职位」先写名称/归属/职责边界/编制，职位说明书不写任职者；再由「登记任职」派人 |
| 一人一主职 | 主要职位有且仅有一个：首次任职自动指定，设为主要职位时同成员其余任职一律降级，免任主要职位时按序自动接续 |
| 主要职位列于首位 | 成员清单按「成员：主要职位、职位、职位」罗列，详情页清单同样首位展示 |
| 事实源唯一 | 页面内容全部由任职事实推导，不另立记录；改一处登记，四页同步刷新 |
| 变更即登记 | 所有写操作必须携带生效日期与变更依据，缺依据不能提交；每次登记生成 `ChangeRecord` |
| 治理优先 | 主要职位建议规则：公司体系下治理职位（创始人、合伙人等）优先，未任治理职位者以经营职位为先 |
| 兼任边界显式 | 登记任职时按职位登记汇报对象；详情卡片逐职位展示汇报链路 |
| 冻结如实标注 | 职位冻结后不再新任职（登记入口置灰 + 数据层拦截），空缺/冻结/超编以徽章标注 |

## 架构分解

应用按 `models/`、`state/`、`screens/`、`widgets/` 四层分解，遵循单向依赖：

```
lib/
├── main.dart                 # 入口：应用装配（主题、作用域、导航框架）
├── models/                   # 数据模型（纯数据、不可变、零依赖）
│   ├── org_unit.dart         #   机构
│   ├── position.dart         #   职位（含权能、类别、状态枚举与文案扩展）
│   ├── member.dart           #   成员
│   ├── appointment.dart      #   任职（兼任、主要职位、汇报对象）
│   └── change_record.dart    #   变更登记
├── state/
│   ├── position_store.dart   #   内存事实源：查询推导 + 登记写操作（ChangeNotifier）
│   └── position_store_scope.dart  # InheritedNotifier 作用域
├── screens/                  # 页面（依赖 state + widgets + models）
│   ├── overview/             #   总览：空缺/冻结/登记缺口聚合 + 最近登记
│   ├── positions/            #   职位页 + 职位详情（页面私有组件）
│   ├── members/              #   成员页 + 成员详情（页面私有组件）
│   └── records/              #   变更登记流水
└── widgets/                  # 通用组件（只依赖 models，两页以上复用才提升）
    ├── navigation/           #   AppShell 导航骨架
    ├── data/                 #   StatusBadge 状态徽章、PowerChip 权能标签
    ├── common/               #   EmptyState 空态
    └── forms/                #   ChangeDialog 登记对话框、AppointDialog 登记任职
```

### 数据流

```
交互（页面） → store 登记方法（校验 + 写事实 + 记 ChangeRecord）
            → notifyListeners → PositionStoreScope 重建依赖页面
读：事实（appointments/positions） → 推导（占用/空缺/清单排序/主要职位） → 展示
```

- **模型不可变**：写操作不改模型字段，而是整体替换或追加，保证登记原子性；
- **推导集中在 store**：空缺、超编、清单首位排序、主要职位唯一性等规则只实现一处；
- **UI 不写规则**：页面只负责收集登记信息（对象 + 生效日期 + 依据）并调用 store。

## 数据规则

| 规则 | 实现 |
|---|---|
| 编制占用 | `filledOf(positionId)` = 该职位在任任职数 |
| 空缺 | 占用为 0（派生状态，不设枚举） |
| 超编 | 占用 > 编制（示警，不拦截登记） |
| 冻结 | `PositionStatus.frozen`：拦截新任，已有任职不受影响 |
| 主要职位唯一 | `_applyPrimary` 同步降级同成员其余在任任职 |
| 自动接续 | 免任持主要职位者 → `suggestPrimaryAppointmentId`（治理优先，同序列按登记先后） |
| 变更登记 | 五类：职位设立、职位变更、新任、免任、主要职位变更 |

## 示例数据

职位清单取自量潮职位实践文档的结构：联盟代表、联盟副秘书长、联盟秘书、联盟秘书长、
实训基地总裁、实训基地副总裁、实训基地代表、仲裁官，另设公司体系的创始人/合伙人以演示治理优先。
示例中含 1 个空缺职位（合伙人）、1 个冻结职位（联盟司库）、1 条已免任任职（苏晚的联盟副秘书长），
以及 9 条变更登记。

## 技术选型

- **框架**：Flutter（全平台客户端：Web / 桌面 / 移动），首发形态 Web
- **状态**：`ChangeNotifier` + `InheritedNotifier`（不引第三方状态库，保持依赖面与惯例一致）
- **版本**：Flutter 3.44.x，SDK `^3.12.2`，`flutter_lints` 静态检查
- **测试**：`test/position_store_test.dart`（规则单测）+ `test/widget_test.dart`（页面与登记流程）
