# 页面设计（screens/）

对应 `index.md` 架构分解中的 `screens/` 层。每页的布局结构、关键交互与登记入口。

导航骨架 `AppShell` 提供四个页面入口：总览 / 职位 / 成员 / 登记。
宽屏（≥720px）左侧导航栏，窄屏底部导航栏；页面切换不保留滚动位置以外的状态。

## 总览（overview/overview_screen.dart）

| 区块 | 内容 | 落点 |
|---|---|---|
| 聚合卡 | 职位数 / 在任成员数 / 空缺数 / 冻结数 | 事实源推导，首页即审计视图 |
| 需要处理 | 空缺职位、超编职位、未指定主要职位的成员 | 手册「不留悬空」的缺口在此暴露；无缺口显示空态 |
| 最近登记 | 最新 5 条 `ChangeRecord`（类型徽章 + 对象 + 生效日期） | 变更即登记的必读处 |

**交互**：只读聚合，具体操作进入对应页面。

## 职位页（positions/positions_screen.dart）

| 区块 | 内容 |
|---|---|
| 机构分组 | 按 `OrgUnit` 分组：`机构名 · N 个职位`，组内按设立顺序排列 |
| 职位条目 | 名称 + 状态徽章（冻结/空缺/超编）+ 职责边界（单行）+ 权能标签 + 编制占用 |
| 新建职位 | FAB → `PositionSetupDialog` |

**交互**：

- 点击条目 → `PositionDetailScreen`（页面私有）；
- 详情页：槽位属性（归属/类别/权能/编制/职责边界）+ 任职者清单（主要职位徽章、汇报对象）+ 操作区：
  - **登记任职**：冻结时置灰并提示「冻结中，不再新任职」；否则打开 `AppointDialog`（预设职位侧）；
  - **冻结/解冻**：打开 `ChangeDialog`，必须登记生效日期与依据；
- 任职者可跳转成员详情（跨页互链，事实仍只有一份）。

## 成员页（members/members_screen.dart）

| 区块 | 内容 |
|---|---|
| 页首说明 | 「事实源唯一：清单由任职登记推导，主要职位列于首位」 |
| 成员条目 | 标题=「成员：主要职位、职位、职位」（两行省略）；副标题=在任机构集合；缺主要职位时挂警示徽章 |

**交互**：点击条目 → `MemberDetailScreen`。

## 成员详情（members/member_detail_screen.dart）

| 区块 | 内容 |
|---|---|
| 职务清单 | 完整清单文本（首位即主要职位），卡片展示 |
| 在任任职 | 每职一张卡片：职位名 + 主要职位徽章、归属·类别、权能标签、汇报对象、生效日期与依据 |
| 操作 | 卡片内「设为主要职位」「免任」；FAB「登记新任职」 |

**交互**：

- 设为主要职位 / 免任 / 登记新任职均弹登记对话框，缺变更依据无法提交；
- 免任持主要职位者时，store 按治理优先自动接续并**另记一条主要职位变更登记**（依据自动追加「一人一主职自动接续」）；
- 免任后卡片随 `active` 事实消失，任职历史保留在数据层。

## 登记页（records/records_screen.dart）

| 区块 | 内容 |
|---|---|
| 页首说明 | 「记录先行，告知随后——生效日期与变更依据逐条载明」 |
| 流水列表 | 每条：类型徽章（主要职位变更=主色、免任=警示、其余=中性）+ 对象 + 生效日期·依据 + 补充说明 + 登记日期 |

**交互**：只读流水；新登记由 store `insert(0, ...)` 置顶。

## 状态与重建

页面通过 `PositionStoreScope.of(context)` 依赖事实源；任一登记完成后 `notifyListeners`
会重建所有依赖页面——因此对话框提交后无需手动刷新，四页内容始终同源。
